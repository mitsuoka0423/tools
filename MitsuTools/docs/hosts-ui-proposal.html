Hosts プロファイル：設定画面とメニューのデザイン案

機能仕様（プロファイル＝行の集合／/etc/hosts は管理区間だけ入替／適用のたび管理者パスワード／hosts.json・config.toml・バックアップ）は変えないまま、「どれが効いているか」「押すと何が起きるか」「いま編集して安全か」が一目でわかる形に組み替えます。

困っていること（レビュー由来）

  • 手が当たって誤変更：編集欄が常にむき出し（→既定読み取り専用に改善済みだが、編集自体が「書き換え＝危険」という印象）
  • 適用の UI が使いにくい：スイッチの意味が分かりにくい／押下前にパスワードを聞かれる
  • 「管理区間を解除」「直前に戻す」が内部語で、何が戻るのか不明
  • 今どこが効いているかが、そのプロファイルを開かないと確認できない
  • エラー（パスワード取消など）に警告ダイアログで怒られる

※hosts.json（プロファイル）と /etc/hosts（適用状態）は別物。ここを画面言語として分離できていないのが根本の原因。

設計方針（5つ）

  1. 状態を先頭にする — 「今適用されているもの」を画面の一番上に大きく出す。真実は /etc/hosts にある。
  2. 副作用は必ずプレビュー after — /etc/hosts を書き換える操作（適用・解除・戻す）は、必ず「変わる行」を見せてから確認し、その後にパスワードを聞く。
  3. 編集と適用を分ける — プロファイルの編集は hosts.json へ自動保存されるだけで、/etc/hosts には何もしない。安心して触れる。効いているものと違う箇所を直したら「反映されていません」のしるしを出す。
  4. 1行1動作 — 行タップ＝選んでプレビュー、適用は専用ボタン。スイッチのように「状態に見えて実は命令」という形は作らない。
  5. 人間の言葉 — 「適用中」「使うやめる」「いまの内容に戻す」。管理区間・バックアップは注記に逃がす。

スイッチは radio のように「これにする」だけ。押した瞬間は hosts.json 上の選択が動き、確認シートで承認するまで hosts は変わらない（シートで取り消せばスイッチも戻る）。

案A との違い

  • 操作数が少ない（慣れるとスイッチ一発＋確認1回）
  • ただし「スイッチ＝命令」の形は残るので、誤タップ→確認画面という安心設計が前提
  • 編集領域は案Aと同じ（未反映バッジ＋自動保存）

「radio にしたスイッチ」は見た目で状態が伝わりにくい（両方オンに見える可能性）ため、案A の方が安全側と判断。

状態の取り決め（実装仕様メモ）

  • 未反映：選んだプロファイルの行と、 hosts 中の管理区間の中身が違う（一致判定は行集合で比較）
  • 一致：hosts に適用中と同一の行（プロファイル自体は hosts.json にのみ存在）
  • /etc/hosts 手変更検出：前回読んだ hosts のうち「管理区間以外」が変わっていたら、注意一行（直す誘導はしない）
  • パスワード取消はエラー扱いしない（シートを閉じただけ＝無かったことにする）
  • 書き込み失敗（権限・読み取り専用）だけ赤い警告。
実装済みの機能（hosts.json・config.toml の active・バックアップ・DNS flush・osascript 方式）はそのまま、画面の組み替えだけで到達できる案です。実装するなら案A：状態カード＋「この中身を適用」＋確認シート（変わる行＋パスワード予告）＋行単位のプレビュー。
