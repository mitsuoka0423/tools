Hosts の画面：アプリの共通パターンに沿った改善案

前回の案はアプリ全体の見え方（Form＋Section＋行、LabeledContent、アイコンボタン、地味なボタン）から離れていました。今回は制約を 「変更してよいのは Hosts ペインの内部だけ。ウィンドウ・タブ・共通ウィジェット・文言の型は他の機能と同じまま」 として、スクリーンショットの組立てをそのままベースに組み直しました。

この画面の評価

  • よかった：レイアウトはアプリの型どおり（Section＋行＋switch＋アイコンボタン）。編集が読み取り専用なのもよい
  • 一番の問題：スイッチ=即書き込みで、触った途端に管理者パスワードを聞かれる（暴発）
  • スイッチが「命令」なのに「適用中」表示も同じ場所にあり、状態と動作が混ざる（オフにすると解除される、が直感とズレる）
  • 「管理区間」など内部語がフッターに出る
  • プロファイルを編集したのに適用していない（未反映）ことが分からない

→ 案1 は、この画面のまま「スイッチ=確認へのはじまり」に変え、行の sub に状態を出し、内部語を消す最小の変更です。

※ いまのスイッチ版 のままとの違いは 2 つだけ：①スイッチ ON/OFF が即書き込みでなく確認ダイアログ経由 ②行の sub に適用状態（適用中／適用待ち）を表示。レイアウトは共通型のまま。

何が変わるか

  • 暴発ゼロ：スイッチは「合図」。実際には変わらない。取り消し＝無かったこと
  • スイッチの意味は1つ（適用/未適用）。選択と分けずに済む
  • 編集欄は読み取り専用＋「編集」ボタン（いまのスイッチ版 のまま。誤変更しにくい）
  • 状態行の「何を待っているか」は行の sub 1 行で表す（カードにしない）
  • 文言：「適用をやめる」の確認のみ新設。「管理区間」は内部語なので画面に出さない（※いまのスイッチ版 ではまだ footer に残っていた→削除）

案1 との違い

  • スイッチがないので「状態の二重表示」が不要。行末の 適用 ボタンが命令そのもの
  • ただし行が混む（適用＋✎＋⊖＋状態）。他の一覧より控件が多い
  • 「適用中」の視覚的しるしが sub テキストだけになる（スイッチ版より弱い）

NSAlert の確認（変わる行＋パスワード予告）は案1 と同じものを使う。

すり合わせたい点

  1. 案1 / 案2 のどちらにするか（他に変えたい形があれば）
  2. 確認ダイアログの文言：「変わる行」の表示は ＋/－/＝ の3種で足りるか（行が多いとき「ほか n 行」の省略でよいか）
  3. パスワードを取り消したとき、スイッチは「押す前」に戻る（＝何も起きない）——これでよいですか
  4. 「適用待ち（編集済み）」sub の言い回し（「 hosts に未反映」等）
  5. メニューの「適用をやめる」でよいか
