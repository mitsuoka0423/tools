Hosts の画面：ラジオ式（案 v2）

ご方針を反映：①同時に有効になることはないのだから、スイッチ（2^n パターンに見える）ではなくラジオボタン（実態の n+1 を正直に見せる）を原則。②メニューバーは「何が選ばれているか」の表示のみ。選択・適用の操作は設定画面で行う。ウィンドウ・タブ・行の型などアプリの共通部分はそのまま、Hosts ペイン内部と確認ダイアログ（NSAlert）だけで成立する案です。

原則の更新案 v2：ラジオ式適用の確認メニュー（表示のみ）実装メモすり合わせ点

原則の更新（v1 からの違い）

v1 までv2（ご方針）
排他的選択の表現行末スイッチ（n 個の ON/OFF ＝ 2^n パターンに見える。実際は n+1）ラジオ：常に1つだけ●。「なし」も1つの選択肢として並ぶ（n+1 をそのまま見せる）
ラジオが表すもの—hosts に今効いているもの（=/etc/hosts の真実）。編集中の「仮選び」ではない
選択（適用）の操作場所設定画面＋メニュー両方設定画面のみ。メニューは状態表示＋設定画面への入口だけ
書き込みのタイミング—ラジオを切り替えたときだけ確認画面 → 承認後にパスワード → hosts へ
アプリの共通型Form/Section/行/LabeledContent/NSAlertそのまま（変更なし）

読み方

  • ● ラジオ＝hosts の真実。「仮の選択」状態は作らない。押すと→確認→承認で初めて動く。取り消せば ● は元の場所に残る
  • 「なし」行で n+1 番目（未適用）を正直に表現。「適用をやめる」ボタンは不要になる（解除もラジオの切り替えと同じ作法でできる）
  • 編集してまだ hosts に入れていないものは sub に「編集済み（未反映）」。● が付いていても「中身が変わっている」ことが1行で分かる
  • 中身（行の一覧）は設定画面に出さない。行数も見せない。行の「見る」ボタンでほかのアプリに開く／編集は「ファイルを編集…」で hosts.json を直接編集する
  • ● の行をもう一度押すと「今の内容で再適用」＝編集後にこれで反映する（差分ゼロなら「変わりません」とだけ出て、パスワードは聞きません）
  • 内部語なし：「管理区間」は画面に出さない（「MitsuTools の行」と書く）

ラジオの見た目は既存の型に収める形（行の先頭に circle／smallcircle.filled.circle アイコン、行タップで選択）を予定。NSButton 本来の radio group は行内アイコンボタンと相性が悪いため、アイコン表現で同じ作法を出します。

適用・解除の確認（NSAlert＝アプリ共通の形）

M

「仕入先」を /etc/hosts に適用しますか？

＋ 10.2.0.31 api.supplier.jp
－ 127.0.0.1 dev.local
－ 0.0.0.0 ads.example.com
このあと macOS に管理者のパスワードを聞かれます。
localhost など MitsuTools の行でないものはそのまま残ります。
M

「なし」に切り替えますか？

－ 127.0.0.1 dev.local
－ 0.0.0.0 ads.example.com
－ 10.2.0.31 db.internal
MitsuTools の行だけが hosts から無くなります。
  • 取り消し＝● は動かず、パスワードも出ない（何もなかったことにする）
  • 差分がゼロの再適用は「変わる行はありません」とだけ表示して終わり（パスワードを聞かない）
  • 失敗（権限など）だけ警告する

メニューバー：選ばれているものの表示だけ

Hosts：適用中「開発」3 行
Hosts の設定…
Hosts：未適用
Hosts の設定…
  • プロファイルの並ぶクリック可能な一覧は廃止（ご方針「選択は設定画面で行う」）
  • 状態は1行のテキスト表示のみ（グレーの無効項目）。クリックも権限ダイアログも起きない
  • 入口として「Hosts の設定…」だけ（タブを開く。設定画面へ飛ぶ導線は EditContext の案内と同じ流儀）

実装メモ（変更範囲は Hosts 機能の内部だけ）

いま（スイッチ式）案 v2
行末 Toggle（appliedSwitch）＋右に「適用中」文字＋「追加…」行頭ラジオアイコン＋「なし」行。Toggle は DNS オプション以外から消える
スイッチ ON→即 apply（パスワード直行）行タップ→NSAlert 確認→承認後 apply（confirmAndApply に一本化）
「適用をやめる」はスイッチの OFF「なし」ラジオへ切り替え＝同じ確認経由。専用のボタンを作らない
メニュー：全プロファイルクリック→即適用＋「管理区間を解除」メニュー：状態1行（無効項目）＋「Hosts の設定…」のみ
中身セクション（読み取り＋編集ボタン）廃止。行の「見る」で他アプリに委譲、「ファイルを編集…」で hosts.json を開く
フッターの「管理区間」語「MitsuTools の行」に統一

共通部品（Form/Section/LabeledContent/Button/アイコン/NSAlert）とウィンドウ・タブの変更はゼロ。データ（hosts.json・config.toml・bak・osascript・DNS flush）も不変。

すり合わせたい点

  1. ラジオ＝「hosts の真実」（仮選び状態なし）という理解で合っていますか。合っていれば「編集済み（未反映）」は sub の注意書きで表現します
  2. 「なし」行の文言：なし（hosts に MitsuTools の行を入れない） でよいですか
  3. メニュー：Hosts：適用中「開発」 3 行／Hosts：未適用 ＋ Hosts の設定… の2項目だけでよいですか
  4. 「中身」を開く対象：既定は●（適用中）の行。他の行をタップしたらプレビューだけ動く（●は動かない）——でよいですか
  5. 差分ゼロの再適用はパスワードを聞かない——でよいですか

OK（または修正点）をいただければ、この案 v2 を Hosts ペイン内部＋NSAlert＋メニュー表示として実装します。
